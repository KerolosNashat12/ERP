The Nexora page was live but still wearing KJ's words, and a stale logo with them

WHAT HE SAW
The new page deployed and the live site still said "KJ", the old hero, the old
three prices, the old indigo. "nothing changes ????????? why"

WHAT WAS ACTUALLY HAPPENING
The new page HAD shipped. Its structure was all there - the systems section,
the clients row, the Nexora mark, the new favicon. What was covering it was
the stored landing document.

This page renders its own defaults and then merges the owner's saved document
over the top, per key. That is the whole design and it is the right one - until
the page stops being the same page. Every key in the stored document described
the old KJ product page: brand.name "KJ", the old SEO title, the old hero, the
three priced packages. Merged over the new defaults, it produced exactly what
he was looking at: the new layout wearing all the old words.

WHAT CHANGES
DOCUMENT_VERSION 1 -> 2.

That field already existed for precisely this, and its own comment says so:
"bump only when the shape changes in a way an older page cannot render." The
stored document is validated on READ as well as on write, and `version` is a
literal in the schema - so a document written under 1 now fails that read, and
the service serves the page's own defaults instead. No console clicks, no
section-by-section restore, no data migration. It takes effect the moment this
deploys.

AND THE SECOND HALF, WHICH IS THE PART THAT WOULD HAVE BEEN MISSED
The logo does not live in the document. It lives in the asset table, and it was
still being minted into brand.logo - so discarding the old words alone would
have left the new page under the old "KJ SOFTWARE COMPANY" mark, which is a
worse result than either. A discarded document now discards its pictures too:
when the stored content is thrown away, the assets uploaded for it are withheld
from the served document.

NOTHING IS DELETED. The bytes stay exactly where they are. The moment a document
at the current version is saved from the console, every upload is minted again
on the next read. A stale picture is hidden, not destroyed.

npm test 1307 -> 1309. The new test stores a picture and a document that is
valid in every respect EXCEPT its version, and asserts both halves: not one word
of the old document survives, and the picture is withheld - then that the same
picture comes straight back once a current document is saved. Verified by
reverting the asset half alone and watching it fail before restoring it. The
tests that spelled the version number as a literal now read the constant, and
the two rows forced into the table to prove read-side validation carry the
CURRENT version deliberately, so the markup and the bad price are what fails
rather than the version number.
