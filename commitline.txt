Pictures were 404 on every hosted shop: an img src with no tenant prefix

THE BUG (photographed on the live shop, brands screen)
Every brand that HAD a logo drew a broken-image icon; every brand without one
drew its letter correctly.

The ERP is one SPA served two ways: at "/" for a shop running it on its own
PC, and at "/t/<slug>/" for a shop on the hosted platform. core/api.js exists
to hide that difference - every fetch it makes is prefixed with apiBase(). An
<img src> never goes through that door; the browser issues the request itself.
So it is the one kind of API call a view can build by hand without anything
noticing, and two views had:

  public/js/views/masterData.js  the brand logo chip, and the preview in its
                                 own dialog
  public/js/views/catalog.js     EVERY product photograph in the catalogue

which means product photos were torn pages for every hosted shop too, not
just brand logos.

It fails silently and ONLY when hosted. On localhost the prefix is empty and
the literal is correct, so nothing in development could ever show it: no
throw, no failed request the UI can see, no rendering test that notices. Just
a small torn page where a picture should be.

THE FIX
Picture addresses are NAMED in core/api.js next to apiBase(), the way the
storefront's own api.js already names imageUrl, brandLogoUrl and
categoryImageUrl: brandLogoUrl, productImageUrl, categoryImageUrl, and
assetUrl(path) as the named escape hatch. A view asks for the address of a
thing; it does not assemble one. brandLogoUrl takes an optional version
because the address carries no id of its own - without it, a replaced logo
keeps showing the old bytes.

HOW IT IS PINNED, TWICE
- tests/asset-urls.test.js reads the three front ends as source and fails on
  any literal /api/... used as a src, href, action or CSS url(); then proves
  the helpers themselves carry the prefix under a /t/<slug>/ location, and
  that the version stamp is present and encoded.
- tests/tenant-assets-check.mjs boots the ERP in PLATFORM mode with its own
  tenant, creates a brand and a product, gives each a picture through the real
  endpoints, opens both screens in a browser at /t/<slug>/ and asks each <img>
  whether it decoded. naturalWidth 0 is exactly what the owner photographed.

Reversion-checked four ways: writing the literal back into the view fails the
source test; removing the prefix from either helper fails the browser check
with his exact symptom; dropping the version stamp fails its own test.

ALSO
- The comment-stripping source scanner is now shared (tests/helpers/source.js)
  instead of living inside one test - a rule written twice diverges, and that
  one has already been wrong once in a way that made a test pass on a broken
  file.
- FIX in this check: it printed "all decoded" unconditionally, including on a
  run where nothing decoded. It reports what it measured now.
